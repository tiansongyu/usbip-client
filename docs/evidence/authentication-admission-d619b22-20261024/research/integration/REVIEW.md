## Confirmed contracts

1. Fixed dependency/API: rootCargo.toml pins governor=0.10.4,default-features=false,features=[std]. Current Cargo.lock checksum matches the independently verified official crate9efcab3c1958580ff1f25a2a41be1668f7603d849bb63af523b208a3cc1223b8. Actual workspace cargo metadata selects governor features[std]; governor-only normal tree excludes quanta,dashmap,rand,getrandom. Whole transport still legitimately contains RNG dependencies for TLS; the first audit-helper assertion incorrectly checked that wider tree and was corrected without product changes.

2. Explicit clock: admission.rs4-9,127-143 fixes RateLimiter<NotKeyed,InMemoryState,C,NoOpMiddleware<C::Instant>>, with productionC=MonotonicClock and direct_with_clock. NoDefaultClock alias can change under feature unification. FakeRelativeClock remains inside tests/private with_clock seam. This matches fixed governor state/direct.rs and clock/default.rs/with_std.rs.

3. Bound proof: AdmissionPolicy fields are private; new()/serdeTryFrom enforceburst1..256 andinterval1..60000ms (admission.rs17-88). Default64/125 is in range. Quota::with_period(Duration::from_millis()).allow_burst(NonZeroU32) matches governor0.10.4 source without per_second division rounding. Maxperiod60,000,000,000ns,maxtau60,000,000,000*255=15,300,000,000,000ns,fullburst15,360,000,000,000ns,all safely belowu64MAX. This does not remove governor's documented~584-year limiter-age/clock horizon; design44-47 correctly retains that boundary.

4. Clone sharing: tls.rs118-125 derivesClone with Arc<Admission>; configured() constructs it once. new/new_with_link select bounded defaults; explicit admission constructors construct one immutable configuration, not per-handshake gates. All configschema1/schema2 server paths pass the parsed policy (config.rs139-148,194-205,232-250,570-587). No reset or refund occurs in clone,monitor or accept paths. Memory-DER callers intentionally can construct another configuration, which has another scope.

5. Cancellation/stream ownership: tls.rs294-305 first takes the existing nonwaiting stream permit. Permit failure records the original TLS ConnectionLimit result without spending rate budget. Rate check then happens synchronously before accept_with/read/write/verifier at308; rejection/poison return drops input and temporarypermit. A positive check consumes governor state before the first handshake await; there is no refund callback/Drop action. The permit subsequently moves into the authenticated stream, preserving prior actual stream ownership. Both raw/framed call the same accept_with_deadline. Existing data streams/driver I/O do not re-enter admission.

6. Metadata-only observer: admission.rs94-124 snapshot contains only scope,policy,numericcounts,flags. AdmissionMonitor holds Arc<Mutex<AdmissionSnapshot>>; limiter stays by value in Admission at129-131, while Admission owns a clone of the monitor. There is no reverse pointer to Admission/limiter, nor credentials,AccessPolicy,stream,connection permit,task,listener orUSB owner. monitor() returns only that metadata clone. Current tests inspect Weak<Admission> after drop, and real TLS test sources also retain monitor after server drop; those tests were read, not executed by this reviewer.

7. Poison and coherent decisions: admission.rs159-181 locks metadata before the synchronous governor check and checked counter increment. Poison maps to AdmissionUnavailable before quota state changes. snapshot() recovers only for inspection, marks consistent=false and never clear_poison(), so observing it cannot re-enable new admission. Counters saturate visibly without wrap; unavailable decisions are not mislabeled as rate-refusals. No await/FS/logging/USB operation or arbitrary user callback occurs in this section. Fixed governor check path samples clock, computes GCRA and accesses AtomicU64; it creates no refill/timer/worker. CAS is not formally wait-free, and stdMutex acquisition is still a short synchronous wait; the design does not claim otherwise.

8. Existing DTO: SecuritySnapshot itself is unchanged in this component. Rate refusals are outside its TLS stage; quota ConnectionLimit remains inside its original category. The new AdmissionSnapshot is independently typed/serialized. serde policy unknownfields/duplicate/zero/outofrange rejection is expressed byPolicyFile deny_unknown_fields andTryFrom, without anenabled=false/null disablingalias.

## Retained limitations

Global per-loaded-configuration limiting does not promise per-peer fairness or prevent an attacker consuming new-admission capacity. Existing authenticated data connections bypass the gate, while stream concurrency budgets remain independent. The fixed governor's broken-clock/extreme-age arithmetic horizon and potentially retryingAtomicCAS remain documented. No bounded hard kernel/syscall latency, persistent audit, hardware isolation or completeG3 is inferred from this review.

Fixed upstream comparison sources are those preserved in the prior read-only research: https://github.com/boinkor-net/governor/tree/9f3a79dd47dd32acd589c562b8d4fefe99b93372/governor/src and official published crate0.10.4.
