# Diagnostic export: fixed-source storage and redaction research

2026-10-24. **Proposed only.** Parent supplied baseline `46cd950`; no Git command, product execution, build, CLI, USB operation or QEMU was run. This report covers serialization, destination safety and blocking ownership. The sibling review owns RPC authorization, snapshot scope and the final bundle schema. The existing requirement is `docs/requirements.md:392–428`; process logging is implemented, while diagnostic export is still outstanding (`docs/research/rotating-logs-design.md:3`).

## Recommendation and smallest API

Use the already locked `serde_json 1.0.154`, `rustix 1.1.5` and Rust `std 1.97.1`. No archive/compression package or new dependency is needed. Deliver one private compact JSON file, rather than a directory or an archive of original files. The caller chooses a local output path; service/helper RPC must never accept a destination path or perform privileged writes on the caller's behalf.

A small implementation boundary is sufficient (names provisional):

```rust
// Concrete closed DTO, not public generic Serialize / serde_json::Value.
fn encode_bundle(bundle: &DiagnosticBundle) -> Result<EncodedBundle>;
// Synchronous; caller owns and joins the accepted blocking operation.
fn prepare_new(path: &Path) -> Result<PreparedOutput>;
fn finish_new(output: PreparedOutput, bytes: EncodedBundle,
              cancelled: &AtomicBool) -> ExportOutcome;
```

Root design subsequently selected preparation of a checked empty staging file before expensive collection. Each prepare/finish call is real owned blocking work; the typed prepared owner carries the original parent/file capabilities between stages. This changes the ordering of the initial research recommendation (encode before creating staging), without permitting any uncapped write or changing publication semantics. `EncodedBundle` should hide its `Vec<u8>` and be constructible only through validation plus bounded encoding. `ExportOutcome` must distinguish `Published`, `NotPublished` (possibly with a private partial artifact), and `PublicationUnconfirmed`. A fixed failure stage/category plus optional OS errno is enough; no arbitrary `Error::Display`, config values or original paths are required in an exported error. Export failure must not poison the business Store, release a lease, or manufacture a root cleanup proof.

Root subsequently selected **4 MiB total encoded bytes including the trailing newline**, finite per-section record/string limits, one owned CLI export at a time, existing private caller-owned parent `0700`, file `0600`, absolute output path at most4096 bytes and one normal bounded basename. The exact per-section counts and final format remain for the root design; the 4 MiB choice is a requested implementation contract, not an executed limit test. Do not silently truncate; reject or include an explicit bounded typed omission count agreed in the schema.

## What the fixed sources support

* `serde_json::to_writer` delegates to the supplied `Write` implementation; it does not impose a size limit. `to_vec` starts a growing vector before serializing, so checking its length afterwards is not a serialization allocation bound (`ser.rs:2177–2222`). Serialize into a private capped writer whose checked addition rejects **before extending** past the cap; validate collection sizes and strings before serialization as well. Reserve at most the fixed cap. JSON escaping can expand UTF-8/control characters, so cap encoded bytes, not only source characters. [Fixed serde_json source](https://github.com/serde-rs/json/blob/20572a6d066958542d79cdd6cf1a7cd9f0c8e1f8/src/ser.rs#L2177)
* JSON escaping and `Serialize` are not redaction. `collect_str` invokes `Display` (`ser.rs:410`), which can disclose an error or secret before a writer sees it. Use a closed allowlist projection; no original logs, config/key/cert bytes, raw USB payload, serial, path, arbitrary maps or free-form error text. Do not attempt to repair those inputs with regex after serialization. A safe alphabet or hash of a low-entropy identifier is not an authorization or anonymity guarantee. [Fixed serializer implementation](https://github.com/serde-rs/json/blob/20572a6d066958542d79cdd6cf1a7cd9f0c8e1f8/src/ser.rs#L410)
* `create_new` rejects any existing target, including dangling symlinks, atomically (`std fs.rs:1785–1820`). `write_all` handles partial writes and Interrupted until completion/error (`io/mod.rs:1858–1870`). `File::sync_all` reports synchronization errors that Drop would ignore (`fs.rs:750–782`); an ordinary stream `flush` is not an fsync substitute. [Fixed Rust1.97.1 fs source](https://github.com/rust-lang/rust/blob/8bab26f4f68e0e26f0bb7960be334d5b520ea452/library/std/src/fs.rs#L1785), [fixed Write implementation](https://github.com/rust-lang/rust/blob/8bab26f4f68e0e26f0bb7960be334d5b520ea452/library/std/src/io/mod.rs#L1858)
* `rustix` provides safe `openat`, `statat`, `fchmod`, `fsync` and `renameat_with`; `RenameFlags::NOREPLACE` maps the Linux no-replacement operation (`at.rs:84–95,302–324`, `fd.rs:124,263`, `backend/linux_raw/fs/types.rs:313–314`). This is enough without new unsafe or a new filesystem package. [Fixed rustix source](https://github.com/bytecodealliance/rustix/blob/287214b889865d8e1406a0ee71cc409b6f6191c8/src/fs/at.rs#L302), [fixed flag](https://github.com/bytecodealliance/rustix/blob/287214b889865d8e1406a0ee71cc409b6f6191c8/src/backend/linux_raw/fs/types.rs#L313)
* An accepted Tokio `spawn_blocking` operation cannot be stopped by abort; executor timeout stops waiting rather than cancelling its real work (`task/blocking.rs:106–120`). Hold its actual JoinHandle and await it after cancellation/shutdown. `O_NONBLOCK` is not a promise that regular-file writes/fsync become cancellable. [Fixed Tokio1.54.1 source](https://github.com/tokio-rs/tokio/blob/b53b2001ed2ccfd9b87e32a0c6da1a1eebdc80b8/tokio/src/task/blocking.rs#L106)

## Repository patterns to reuse, and one incompatibility

`crates/rustusb-logging/src/storage/linux.rs:51–169` already walks parent components through directory FDs, rejects symlinks/writable or wrong-owner ancestors, pins the private leaf, checks regular/uid/0600/nlink1, and rechecks FD/entry identity. Its rotation uses `renameat_with(NOREPLACE)` at542. This is the closest safe ordinary-user output pattern. `Source` is metadata-only; it is not an output capability. Reuse a small checked-directory pattern if needed, **not** `Storage::open`, which would create log locks/headers/rotation state in the output directory.

`crates/rustusb-service/src/fs.rs:21–133` demonstrates protected root-owned ancestry and pinned entry identity; its trust policy is stricter than ordinary-user output. `Store::commit` (`store.rs:407–460`) deliberately replaces `state.json` with plain `renameat`, and a failure poisons the business journal. It is unsuitable as a no-overwrite diagnostic writer. Do not copy its replacement or poison behavior. Keep export detached from all runtime/store mutation locks and USB capabilities.

## Concrete publication sequence

1. Validate the destination and safely prepare the fresh private staging owner before expensive collection (steps2–3); refuse an existing final entry. Then finish the authorized typed snapshot, validate all counts/strings, and fully encode into capped memory **before writing the bundle bytes**. A prepared empty file is not a valid document. The snapshot is metadata, not a current ownership proof.
2. Check the existing private parent by descriptor-relative component walk with `DIRECTORY|NOFOLLOW|CLOEXEC`. Reject traversal, symlinks, group/other-writable ancestors and wrong-owner ancestors. Pin parent dev/ino/uid/mode; re-open/recheck the path before publication. `NOFOLLOW` on only the final file would not protect ancestors. Do not chmod existing directories, change umask globally, use `mkdir_all`, or fall back to `/tmp`.
3. Create a fresh internally generated `.rustusb-diagnostic-<id>.partial` in that pinned directory using `CREATE|EXCL|NOFOLLOW|NONBLOCK|CLOEXEC|WRONLY`, mode0600. Collision must fail or use a bounded new-ID attempt; never remove another existing name. Set permissions on the **new FD only**, then require regular file, actual caller UID,0600,nlink1 and matching FD/entry dev+ino. If parent creation is later desired, explicitly create only a private leaf under an already checked parent, not arbitrary missing ancestry.
4. `write_all` the bounded bytes; `sync_all` the file; recheck size, entry identity, owner/mode/nlink and parent identity. Retain the original FD throughout. A same-UID/root adversary can still interfere; those principals are trusted, and accidental changes must be detected where observable.
5. Publish within the same parent via `renameat_with(NOREPLACE)`. This is the race-safe no-overwrite boundary; a prior existence check alone is insufficient. An existing file, directory or symlink must remain untouched. If the kernel/filesystem cannot provide this operation, fail closed; no fallback to replacing rename, copy-over-existing or unlink-then-rename.
6. Sync the directory FD, then verify that the final entry is the same new inode with expected size/type/uid/mode/nlink. Only then return Published. This uses the filesystem's synchronization contract; it does not claim storage-hardware power-loss certification. Close the owned FDs before returning the worker result.

One staging file disappears on success, leaving one JSON artifact. There is no extra persistent lock/journal/rotation framework: EXCL and NOREPLACE arbitrate concurrent output names. A direct create-new final file is simpler but exposes an empty/partial final name on write failure; staging avoids presenting that as a valid complete bundle.

## Failure, cancellation and output contract

A logically incomplete observation is distinct from filesystem failure: root selected a valid bounded bundle with `complete=false`, typed unavailable/unconfirmed sections and exit1 when collection is incomplete. It may be successfully published using the full sequence above. A `.partial` file is an unpublished filesystem artifact, never this logical partial result. A complete bundle also must not imply complete hardware/security qualification.


Before creation, failure/cancellation produces no artifact. Cancelling after the early prepare may leave an empty private staging file; do not imply that every retained partial is parseable JSON. After staging creation but before rename, preserve the private partial file and report NotPublished; do not call it a valid bundle. After successful rename, a directory-sync or identity error is **PublicationUnconfirmed**: a final entry may already exist. Do not delete or overwrite it, and do not claim cancellation prevented publication. No automatic stale-partial cleanup or business recovery is needed in this slice. SIGKILL/power failure may leave partial/uncertain artifacts; this design does not make those cases successful.

The owned synchronous worker checks a sticky cancellation flag between stages. Once a real blocking syscall is entered, the async owner still waits for its actual completion; no `select!` branch may drop a started worker and report completion. A hard-blocking filesystem is an honest remaining shutdown limitation. No USB handle, helper transaction, state-WAL lock, or device owner should be retained by the export worker.

Bundle JSON goes only to the private file. Stdout may carry a small fixed receipt; stderr uses fixed categories/errno, not the bundle. A stdout delivery timeout after Published is an independent delivery error, not evidence that no file exists. A user retry must still refuse an existing destination. Do not silently send the bundle to stdout as a fallback.

The doctor DTO is not already a shareable projection: `native/src/diagnostics.rs:65–124` contains detail/action/path/kernel-release/tool-version strings. Even a version constrained to ASCII (`836–850`) is not automatically privacy-free. Keep fixed status/module/tool enums and explicitly approved booleans; omit raw details. A single-profile bundle must not include helper `active_sessions` across the full device pool (`daemon/src/diagnostics.rs:33–55`); sibling review owns authorization and permitted field choices. Public certificate bytes are not automatically necessary just because they are not private keys.

## Dedicated collector runtime and child ownership

Root selected a new nonempty `rustusb-diagnostics` library, default Native/helper observations, with optional service support for one-profile postcommit snapshot/pages and separate health/log projections. This is more than repackaging `doctor --json`; it does not make full doctor DTOs safe to serialize. No implementation or new dependency was added in this research.

An owned synchronous collector task may build its **own** Tokio runtime, call `block_on` on the bounded asynchronous collection, then explicitly drop that runtime **inside the same synchronous task**, before returning its report. The outer async owner must join that one task on success, error and cancellation. Runtime shutdown drops ordinary async tasks at yield points, whereas its blocking pool waits for already-started operations (`runtime/runtime.rs:30–55,505–522`; `runtime/blocking/pool.rs:314–347`). `tokio::fs::asyncify` uses `spawn_blocking` (`fs/mod.rs:323–332`). Therefore a timeout of the high-level FS future does not prove the real filesystem work ended; normal Drop of this dedicated runtime joins its blocking pool before the collector can return. [Fixed Runtime](https://github.com/tokio-rs/tokio/blob/b53b2001ed2ccfd9b87e32a0c6da1a1eebdc80b8/tokio/src/runtime/runtime.rs#L30), [blocking-pool Drop](https://github.com/tokio-rs/tokio/blob/b53b2001ed2ccfd9b87e32a0c6da1a1eebdc80b8/tokio/src/runtime/blocking/pool.rs#L343), [FS bridge](https://github.com/tokio-rs/tokio/blob/b53b2001ed2ccfd9b87e32a0c6da1a1eebdc80b8/tokio/src/fs/mod.rs#L323)

Do not move/drop this runtime inside an async poll, use `shutdown_timeout`/`shutdown_background`, or return handles still bound to it. Ordinary spawned async jobs/readers must be explicitly joined first; Runtime Drop is not their successful completion. Keep the runtime and output-write worker ownership simple and avoid blocking-pool recursion where all workers wait for work queued to the same exhausted pool. The dedicated runtime can still wait indefinitely on a hard-blocking filesystem; no finite observation deadline revokes a kernel operation.

A child is a separate ownership problem. Tokio defaults to allowing it to continue after handle Drop; `kill_on_drop(true)` only attempts to kill, and reaping is best effort (`process/mod.rs:197–224,1123–1128`). `start_kill` only requests death. `kill().await` invokes `start_kill` then `wait`; `wait` is cancel-safe and `try_wait` reaps only on `Ok(Some(status))` (`1240–1259,1326–1330,1379–1426`). Do not cancel/drop the last child owner after initiating kill. Retain it and explicit output-reader tasks through actual wait/drain/join, or report a typed unconfirmed observation; never infer reaping from socket EOF, elapsed timeout or dedicated runtime Drop. Descendants are not covered by waiting only the direct child. [Fixed process implementation](https://github.com/tokio-rs/tokio/blob/b53b2001ed2ccfd9b87e32a0c6da1a1eebdc80b8/tokio/src/process/mod.rs#L197)

Existing `native::diagnostics::failed_child` (`crates/rustusb-native/src/diagnostics.rs:795–815`) intentionally bounds its wait to two seconds and distinguishes reaped/unconfirmed only in a detail string. It is a prerequisite observation, not a public total-process-join proof. The exporter must not parse that prose into a stronger claim or silently discard the distinction while saying all children ended. The new design explicitly adds an export-specific child-reaping API, preserving the old doctor interface; it must retain the real child until the required wait is observed and expose a closed typed result. This is the chosen contract, not an implemented result in this report. This does not require running a management subcommand or any host USB operation.

## Meaningful validation to implement later

No following test was run in this research turn:

* Exact encoded cap including newline and escaping; rejected oversize DTO/counts; sentinel raw payload/secret/error Display never evaluated or included.
* Ordinary-user real FS: new0600 under varied umask, existing target unchanged, dangling symlink/hardlink/FIFO/directory refusal, unsafe ancestors, leaf replacement/identity change, and two concurrent publishers with exactly one no-replace winner.
* Actual partial write/write-zero/Interrupted/fsync failure; retained private partial; post-rename directory-sync failure reported as uncertain, never success or absent.
* Accepted worker held at a real/safe injectable I/O boundary: cancellation cannot release its ownership/permit before actual return, and no business WAL/USB lock is held. Releasing the gate must join that same operation rather than launch a retry.
* Small receipt stdout blocked after publication: file outcome stays distinct from output outcome, signal cleanup still joins, and a second invocation cannot overwrite it. No host USB or privileged helper operation is needed for these tests.

## Quick review of the root design

Read `docs/research/diagnostic-export-design.md:56–75`: no blocking mechanism issue found in its storage/cancellation contract. It correctly chooses early checked staging, retained accepted blocking tasks, explicit export-child reaping, 4MiB capped encoding, NOREPLACE+file/directory synchronization, and truthful partial/post-rename receipts. No implementation or runtime result is inferred. Existing-final refusal during prepare does not replace the final NOREPLACE boundary. The early staging owner must not acquire USB or business-WAL capabilities.
